# باقات الأنشطة وعزل الحسابات

التسجيل ذاتي، والتفعيل المجاني لا يحتاج موافقة أدمن. تخصيص الباقات وظيفة منصة، وتعيين موظفي النشاط وظيفة مالكه أو مديره المخول.

## الباقات

- تبقى الباقات الأربع الموجودة (مجانية، أساسية، احترافية، أعمال). لا تُغيّر الأسعار أو اشتراكات العملاء المدفوعة تلقائيًا.
- الإعداد المشترك للباقة هو الأصل. صف `package_plan_activity_features` يخصص ميزة واحدة لنشاط واحد داخل الباقة نفسها، وله الأولوية على الأصل.
- `enabled=false` إيقاف صريح؛ `limit_value=0` يمنع إضافة سجلات؛ `NULL` بلا حد. حذف التخصيص يعيد الإعداد المشترك، بما فيه الحد.
- للأدمن اختيار أي نشاط من الأنشطة الـ15 وتعديل تفعيله وحدوده، أو استعادة الإعداد المشترك. Support يقرأ فقط. كل تعديل واستعادة يُسجّل في التدقيق.
- الترحيل 0093 يضع تخصيصات مجانية لكل الأنشطة من الإعدادات الحالية، ويحافظ على الإيقاف الصريح، ويحد الكتالوج افتراضيًا بحد أقصى 20 صنفًا/خدمة و20 قسمًا. الحدود الأصغر المحفوظة لا تُرفع. الحدود قابلة للتخصيص لاحقًا.
- حد الكتالوج يحسب السجلات المحفوظة، بما فيها المعطلة. يشمل الإدخال المباشر، المسارات القديمة، وحدات التشغيل والاستيراد. قفل اشتراك المستأجر يمنع تجاوز الحد بطلبين متزامنين.
- هذا ليس حدًا شهريًا لعدد الطلبات أو مساحة صور جديدة. مساحة الوسائط لها سياسات الأدمن الحالية؛ لا يجوز الادعاء بتطبيق حد مبيعات أو تخزين إضافي لم يُختبر.
- الواجهة وقرارات الخادم وقراءة كتالوج Edge ومزامنته وبدء الدفع تستخدم تخصيص النشاط. الميزة المدفوعة لا تمنح صلاحية موظف؛ والدور لا يتجاوز الباقة.

## الأدوار

| الحساب | وظيفته | نطاقه |
|---|---|---|
| Super Admin / Admin | الباقات والاشتراكات والحسابات وإعدادات المنصة وفق الدور | إدارة المنصة؛ لا عضوية مالك تلقائية بأي متجر |
| Support | القراءة الإدارية المسموح بها | لا تعديل باقات ولا تشغيل متجر بصفة المالك |
| المالك | إعداد النشاط ومنح الموظفين الأدوار والفروع والصلاحيات | نشاطه الذي يملك عضويته فقط |
| المدير | إدارة التشغيل والموظفين حسب السياسة | نشاطه وفرعه؛ حساب تشغيلي وليس حساب شراء شخصي |
| الكاشير | البيع وإجراءاته المصرح بها | النشاط والفرع والأذونات الممنوحة |
| النادل / المشرف | الصالة والطاولات والنداءات المصرح بها | النشاط والفرع والتكليف |
| المطبخ | عرض التحضير وتحديثاته المصرح بها | قسم وفرع النشاط |
| السائق | التوصيل المصرح به | النشاط والفرع والتكليف |
| المحاسب | الفواتير والتقارير المصرح بها | النشاط والفرع والأذونات |
| العميل | الشراء وطلباته وحسابه ومكتبته الشخصية | بياناته فقط؛ لا عضوية موظف تلقائية |

الموظف تابع للنشاط الذي أضافه. العمل في أكثر من نشاط يحتاج عضويات وأذونات مستقلة ولا ينقل أي منح بين الأنشطة. حساب يحمل عضوية غير المالك يُعامل حسابًا تشغيليًا؛ لا شراء ولا API عميل ولا مكتبة شخصية ولا تسجيل نشاط إضافي منه. إيقاف الموظف لا يحوّله إلى عميل. حتى وجود ربط عميل تاريخي لا يعيد فتح هذه المسارات. لا يُحذف الربط التاريخي أو السجلات السابقة تلقائيًا.

واجهة الموظف تخفي المكتبة الشخصية. الحماية أيضًا على الخادم لواجهات العميل وروابط المتاجر الشخصية والمكتبة وقراءة الصور الخاصة. أدوات النشاط المصرح بها تظل مستقلة.

## التحقق والنشر

اختبارات مستقلة في `activity-plan-settings.integration.test.mjs` و`account-surface.integration.test.mjs` مع قاعدة `foon_migration_test` محلية فقط. اختبارات المتصفح والعمليات تبقى مطلوبة أيضًا. نجاحها لا يثبت إرسال بريد حقيقي أو دفعًا حقيقيًا.

يلزم تطبيق `0093_activity_plan_features.sql` عبر عامل الترحيلات المعتاد قبل تشغيل الكود الجديد، بعد نسخة احتياطية وخطة مراجعة على الإنتاج. لا تسجل الترحيل كمطبق يدويًا قبل تنفيذ المخطط. هذه التغييرات لا تنفذ ترحيلًا أو نشرًا على الإنتاج.
